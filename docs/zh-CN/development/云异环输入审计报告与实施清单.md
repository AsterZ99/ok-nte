# 云异环输入审计报告与实施清单

本文记录 `feat/cloud-nte-adaptation` 分支的输入安全与实现一致性审计结果, 并定义
“子窗口消息点击”方案的施工边界、工作包、验证矩阵和验收条件。后续 agent 应以本文为
执行清单, 但仍需通过真实云客户端探针取得能力证据后才能接入正式任务。

| 项目 | 值 |

| 默认降级策略 | 失败关闭; 禁止静默降级到前台物理输入 |

!!! danger "审计结论"

    当前鼠标实现不能作为正式云模式输入后端。它在前台切换失败后仍可能发送全局
    `mouse_event`, 坐标和窗口目标也没有在同一快照中完成验证。这既能解释“部分点击
    生效”, 也存在误点其他窗口的安全风险。

    后续实现应先恢复一条独立的子窗口消息点击路径, 在真实客户端上完成受控能力矩阵。
    在证据不足或目标失效时必须拒绝派发, 不能自动切换到会抢前台或移动真实光标的实现。

## 2. 当前输入路径

当前实现同时包含三种语义不同的输入方式:

```text
键盘
  -> 假激活 WLCloudGameClient
  -> PostMessage 键盘消息

鼠标移动
  -> PostMessage(WM_MOUSEMOVE)

鼠标按钮与滚轮
  -> 尝试把云主窗口切到前台
  -> 移动真实系统光标
  -> 全局 mouse_event
```

因此“键盘正常”和“鼠标仅部分生效”并不矛盾。键盘有明确的 HWND 目标, 当前鼠标按钮则
进入全局输入流, 依赖真实前台、光标位置、串流客户端采样时机和用户是否同时操作鼠标。

## 3. 审计发现

### 3.1 严重度定义

| 级别 | 定义 |
| --- | --- |
| P0 | 可能向非目标窗口发送输入或破坏输入释放合同, 接入任务前必须修复 |
| P1 | 会造成明显功能错误、窗口重建失败或任务不可恢复, 正式接入前必须修复 |
| P2 | 维护、诊断或兼容性风险, 应在同一适配阶段处理 |
| P3 | 清理和工程卫生问题, 不阻塞探针但阻塞合并 |

### 3.2 发现汇总

| 编号 | 级别 | 发现 | 结论 |
| --- | --- | --- | --- |
| A-01 | P0 | 前台确认失败后仍发送全局鼠标事件 | 必须改为失败关闭 |
| A-02 | P0 | 输入子窗口缺失时回退到其他 HWND | 必须拒绝派发 |
| A-03 | P1 | 坐标映射只按宽高缩放且使用过期几何 | 建立显式内容区合同 |
| A-04 | P1 | 拖拽混用消息移动与物理按钮 | 统一后端和事务状态 |
| A-05 | P1 | 停止或异常时不能保证释放鼠标按钮 | 增加配对状态与清理 |
| A-06 | P1 | 截图健康检查不是每次输入的真实门禁 | 移到派发边界 |
| A-07 | P1 | Launcher 未复用唯一目标解析器 | 多目标时可能选错进程 |
| A-08 | P1 | 本地和云同时运行时静默优先云 | 增加明确选择合同 |

### 3.3 详细发现与整改合同

#### A-01: 全局点击未对前台失败关闭

证据: `src/interaction/CloudNTEInteraction.py:263-315`。

`_bring_cloud_to_front()` 使用 `None` 同时表达“已经在前台”“切换失败”和“目标无效”。
`_physical_button()` 不检查结果, 仍会调用全局 `mouse_event`。

风险:

- 焦点仍在编辑器、浏览器或其他应用时发生误点;
- 固定等待期间焦点被用户或系统抢走后发生竞态;
- 当前代码无法从日志中区分安全点击和错误窗口点击。

整改要求:

- 默认云鼠标后端不得调用全局物理输入 API;
- 若保留物理模式, 必须成为用户显式选择的独立后端;
- 物理模式必须返回明确的前台获取结果, 失败时不得发送按钮事件。

验收:

- 模拟前台切换失败时, `SetCursorPos`、`mouse_event` 和 `SendInput` 调用数均为零;
- 后台消息模式完全不调用这些 API。

#### A-02: 子窗口缺失时错误回退

证据: `src/interaction/CloudNTEInteraction.py:93-102`。

`cloud_input_child()` 返回 0 后, `hwnd` 属性回退到父类 HWND。重连、窗口树重建或版本变化时,
输入可能被投递到云主窗口或其他并未验证的窗口。

整改要求:

- 云模式下输入目标只能是当前快照中验证通过的叶子窗口;
- 子窗口链缺失、PID 不一致或多目标歧义必须返回阻止原因;
- 不允许以父窗口、中间窗口或上次缓存的 HWND 自动兜底。

验收:

- 子链任一节点失效时没有任何输入消息;
- 重建后的新 HWND 只有完成重新解析和健康检查后才可接收输入。

#### A-03: 坐标合同不足

证据: `src/interaction/CloudNTEInteraction.py:191-202, 302-305`。

当前映射仅比较截图宽高与子窗口客户区宽高, 然后做全尺寸比例缩放。它没有表达主窗口客户区、
串流内容区、黑边、DPI 虚拟化和叶子窗口在主窗口中的偏移。屏幕坐标还在恢复窗口之前计算,
窗口几何变化后继续使用旧坐标。

整改要求:

- 一个派发只能使用一个不可变目标快照;
- 快照显式记录 capture size、content rect、leaf client rect 和必要的屏幕变换;
- 截图点先验证位于内容区, 再归一化映射到叶子客户区;
- 所有边界使用半开区间, 禁止对越界坐标做静默夹取。

验收:

- 纯函数测试覆盖等尺寸、比例缩放、内容区偏移、黑边、边界和越界拒绝;
- 实机九宫格测试没有随位置增大的系统性偏差。

#### A-04/A-05: 拖拽语义不一致且缺少释放保证

证据: `src/interaction/CloudNTEInteraction.py:251-360, 385-392`。

`move()` 投递 `WM_MOUSEMOVE`, `mouse_down()` 和 `mouse_up()` 使用全局事件。停止任务、窗口消失
或异常发生在 down/up 之间时, 没有统一状态保证抬起。

整改要求:

- 消息后端的 move/down/up/drag 必须全部投递到同一叶子窗口;
- 按住左键移动时, 每条 `WM_MOUSEMOVE.wParam` 必须包含 `MK_LBUTTON`;
- 后端保存有限的按钮状态, `on_destroy` 和异常清理只对已确认按下的按钮补发抬起;
- 第一阶段若拖拽未通过实机矩阵, 对外能力应明确为不支持, 不能混用物理输入补齐。

验收:

- 单测覆盖正常拖拽、派发中异常、窗口重建和销毁清理;
- 任务停止后没有粘住的逻辑按钮状态;
- 不出现跨 HWND 的 down/up 配对。

#### A-06: 健康检查没有形成输入门禁

证据: `src/tasks/BaseNTETask.py:964-1001`, `src/tasks/NTEOneTimeTask.py:7-13`。

健康检查目前主要在一次性任务进入时执行, 且应用到所有运行目标。任务运行中发生黑帧、重连、
尺寸变化或 HWND 重建后, interaction 仍能继续派发。`expected_size` 没有传入,
`SIZE_CHANGED` 分支不能参与运行时判断。

整改要求:

- 云输入快照必须包含最近健康帧的时间和尺寸;
- 每次消息派发在锁内检查快照新鲜度和 HWND 有效性;
- 健康检查只在云运行目标启用, 不改变本地异环现有行为;
- 输入层只读取轻量状态, 不在派发热路径执行 OCR、模型推理或完整截图。

验收:

- 黑帧、过期帧、尺寸变化、无效 HWND 和目标歧义均阻止下一次输入;
- 本地异环相关测试和行为不变。

#### A-07/A-08: Launcher 的目标选择不唯一

证据: `src/tasks/LauncherTask.py:84-104, 410-457`。

Launcher 先选择 `_find_process()` 返回的一个进程, 再在该 PID 下寻找窗口, 没有复用
`resolve_cloud_target()` 的多目标失败关闭合同。本地异环与云异环同时运行时还会静默优先云。

整改要求:

- Launcher 和 interaction 使用同一目标解析服务;
- 多个满足条件的云目标不得自动选择;
- 本地和云同时存在时使用显式配置或用户选择, 不依赖检测顺序;
- 运行中目标重建应进入重新绑定状态, 而不是继续使用旧目标。

验收:

- 多进程重叠、双目标、本地与云并存都有确定测试;
- 没有明确目标时 `game_capture_ready` 保持 false。

#### A-09: 持续假激活影响真实鼠标

证据: `src/interaction/CloudNTEInteraction.py:54-69, 128-146`。

持续线程每 3 秒向云输入子窗口发送激活消息。现有实机记录表明, 云客户端在这种状态下可能持续
读取用户真实鼠标移动, 即使没有脚本输入也会转动游戏视角。

整改要求:

- 消息探针同时测试“仅派发期间激活”和“短租约激活”;
- 若键盘必须持续激活, 激活租约应与任务生命周期绑定并可观察;
- 任务停止、窗口消失和 interaction 销毁时立即释放;
- UI/日志应说明后台激活可能影响真实鼠标, 但日志不记录用户路径或隐私数据。

#### A-10: 鼠标关键路径没有测试

证据: `tests/test_cloud_integration.py:218-260` 仅覆盖键盘分发。

需要补充的最小测试:

- 目标快照有效/无效;
- 子窗口缺失时不回退;
- 左、右键消息顺序及 lParam;
- drag 的按钮标志和 down/up 配对;
- 滚轮的屏幕坐标;
- 激活释放顺序;
- 异常和销毁清理;
- 确认后台消息模式没有调用前台或全局鼠标 API。

#### A-11: 探针不能作为当前实现证据

证据: `tools/cloud_input_probe.py:113-120, 195-220`。

- `--target-hwnd` 参数已定义但未使用;
- `WM_MOUSEWHEEL.lParam` 当前填入客户区坐标, Windows 合同要求屏幕坐标;
- 探针没有记录派发前后的前台窗口和系统光标位置, 无法证明“未抢前台/未移动光标”。

整改要求:

- 修复参数和滚轮坐标;
- 探针输出目标链、PID、窗口矩形、DPI、截图尺寸、前台 HWND 和光标前后值;
- 输出继续强制保存在仓库外, 不提交截图、窗口标题全集或用户环境路径。

#### A-12/A-13/A-14: 文档、兼容性和工程卫生

- 原设计文档 2026-09-16 的“封装完成”段落声称鼠标不移动真实光标, 与当前物理实现相反;
- `Qt51517QWindowIcon` 和中文标题是当前证据下的严格身份条件, 客户端更新后可能变化;
- 当前工作区的 `uv.lock` 存在与功能无关的镜像源替换, `tests/.tmp/` 未被忽略。

整改要求:

- 保留严格身份匹配, 同时在解析失败时输出脱敏诊断, 禁止用模糊标题直接放行;
- 合并前同步设计、能力矩阵和用户可见限制;
- 不把无关锁文件改动或测试临时文件带入云适配提交。

## 4. 技术决策: 子窗口消息点击

### 4.1 决策

第一候选实现为纯后台 `CloudMessagePointer`:

- 目标固定为经验证的 `WLCloudGameClient` / `WLCloudGame` 叶子窗口;
- 鼠标位置和按钮使用窗口消息表达;
- 派发期间不改变 Windows 前台窗口;
- 不移动真实系统光标;
- 不调用 `mouse_event`、`SendInput` 或合成指针 API;
- 不成功时返回结构化结果, 不自动降级到物理输入。

该决策的依据不是“窗口消息必然可用”, 而是它是当前安全边界内唯一同时满足 HWND 定向、
不抢前台和不移动真实光标的候选。其可用能力必须由真实客户端矩阵决定。

### 4.2 明确非目标

本阶段不实施:

- 进程注入、DLL 注入、API Hook、内存读写或云协议逆向;
- 内核鼠标驱动、Raw Input 伪造或低级输入过滤器;
- 为规避目标检查而修改客户端窗口过程;
- 静默切前台、瞬移真实光标或全局物理点击;
- 在没有实机证据时承诺拖拽、滚轮或相对视角移动可用;
- 将虚拟手柄作为本工作包的一部分。虚拟手柄可在消息点击结论之后单独立项。

### 4.3 后端边界

建议将目标解析、门禁和消息构造从 `CloudNTEInteraction` 中拆出, 保持 interaction 只负责
框架适配:

```text
CloudNTEInteraction
  |
  +-- CloudTargetResolver     解析唯一主窗口和叶子窗口
  +-- CloudInputGate          验证快照、帧健康和坐标
  +-- CloudMessagePointer     构造并投递鼠标消息
  +-- CloudKeyboardDispatcher 保留已验证键盘配方
```

建议文件职责:

- `src/interaction/cloud_window.py`: 窗口记录、唯一目标解析、纯函数健康判断;
- `src/interaction/cloud_mouse.py`: 坐标转换、消息构造、按钮状态和结构化结果;
- `src/interaction/CloudNTEInteraction.py`: ok-script API 适配和生命周期;
- `tools/cloud_input_probe.py`: 受控实验, 不承载生产策略;
- `tests/test_cloud_mouse.py`: 新后端的纯逻辑和消息序列测试。

不要仅为减少函数长度继续拆分无状态包装器。新的模块边界应对应可独立测试的输入合同。

## 5. 数据合同与输入门禁

### 5.1 不可变目标快照

建议引入不可变数据结构 `CloudInputSnapshot`。最小字段:

```python
@dataclass(frozen=True)
class CloudInputSnapshot:
    main_hwnd: int
    leaf_hwnd: int
    process_id: int
    capture_size: tuple[int, int]
    content_rect: tuple[int, int, int, int]
    leaf_client_size: tuple[int, int]
    frame_health: CloudFrameHealth
    frame_observed_at: float
    generation: int
```

说明:

- `content_rect` 使用截图坐标, 表示真实串流画面, 不把黑边计入可点击区;
- `generation` 在目标重建、尺寸变化或重新绑定时递增;
- 一个输入事务只能使用创建时的同一个 snapshot;
- 不在同一点击中多次调用 `self.hwnd` 取得可能不同的叶子窗口。

### 5.2 结构化结果

消息派发不要仅返回 `True/False`, 建议返回:

```python
CloudDispatchResult(
    status=SENT | BLOCKED | FAILED,
    reason=NONE | NO_TARGET | AMBIGUOUS_TARGET | STALE_FRAME |
           UNHEALTHY_FRAME | SIZE_CHANGED | OUT_OF_BOUNDS |
           WINDOW_REBUILT | POST_FAILED | UNSUPPORTED,
)
```

任务层可以按状态中止或重试, 但不得把 `BLOCKED` 当作成功。

### 5.3 每次派发的门禁顺序

在 interaction 输入锁内依次验证:

1. 运行目标明确为 Cloud;
2. 主窗口和叶子窗口均为有效 HWND;
3. 两个窗口仍属于 snapshot 中的 PID;
4. 当前解析链仍指向 snapshot 中的 leaf HWND;
5. 没有多个满足正式身份条件的目标;
6. 最近健康帧未超过约定时限;
7. 截图尺寸和 snapshot 合同一致;
8. 输入点位于 `content_rect`;
9. 转换后的叶子客户区坐标有效;
10. snapshot generation 在投递前未改变。

任何一步失败都返回 `BLOCKED`, 且不发送激活、移动、按钮或滚轮消息。

## 6. 坐标转换合同

输入坐标来自截图。转换分两步:

```text
capture point
  -> 去除 content_rect 左上偏移
  -> 在 content_rect 内归一化
  -> 映射到 leaf client size
  -> leaf client point
```

纯函数形式建议为:

```python
map_capture_to_leaf(point, capture_size, content_rect, leaf_client_size)
```

要求:

- 使用截图和叶子窗口各自的客户区, 不混用窗口外框矩形;
- 显式处理内容区偏移, 不能只比较两个全尺寸宽高;
- 转换前拒绝负值和内容区外坐标;
- 转换后验证 `0 <= x < width`、`0 <= y < height`;
- 取整策略固定并通过测试, 推荐四舍五入后再做边界验证;
- DPI 信息进入诊断记录, 但只有出现逻辑/物理像素差异证据后才引入额外换算。

滚轮是例外: `WM_MOUSEWHEEL.lParam` 使用屏幕坐标。应从已验证的叶子客户区点调用
`ClientToScreen`, 并用有符号 16 位坐标正确打包, 兼容位于虚拟屏幕负坐标区域的显示器。

## 7. 消息序列

### 7.1 基础点击候选

生产候选序列:

```text
SendMessageTimeout(leaf, WM_ACTIVATE, WA_ACTIVE, 0)
PostMessage(leaf, WM_MOUSEMOVE, 0, point_lparam)
PostMessage(leaf, WM_LBUTTONDOWN, MK_LBUTTON, point_lparam)
等待可配置的最短按压时间
PostMessage(leaf, WM_LBUTTONUP, 0, point_lparam)
PostMessage(leaf, WM_ACTIVATE, WA_INACTIVE, 0)  # 仅在实测允许按次释放时
```

这只是首个实验候选, 不是未经实测即可固定的最终配方。探针应比较同步和异步投递、是否需要
短时激活租约, 但生产实现只保留有证据支持的最小序列。

### 7.2 右键

右键使用同一坐标和生命周期, 仅替换为:

- `WM_RBUTTONDOWN` + `MK_RBUTTON`;
- `WM_RBUTTONUP` + 0。

不得调用 `click(..., key="right")` 后在底层切换到物理标志。

### 7.3 长按和拖拽

仅在点击矩阵通过后继续验证:

```text
MOVE(start, 0)
LBUTTONDOWN(start, MK_LBUTTON)
MOVE(p1, MK_LBUTTON)
MOVE(p2, MK_LBUTTON)
...
MOVE(end, MK_LBUTTON)
LBUTTONUP(end, 0)
```

路径点应由已有 swipe 插值结果提供, 不在 UI 线程生成或等待。窗口 generation 改变时停止发送
后续 MOVE, 并仅向原 leaf HWND 尝试一次安全的 BUTTONUP 清理。

### 7.4 激活租约

依次验证以下最小策略:

1. 不激活, 只发鼠标消息;
2. 每个事务同步 `WA_ACTIVE`, 输入后排队 `WA_INACTIVE`;
3. 在短时间租约内维持激活, 空闲后释放;
4. 只有键盘维持激活, 鼠标不改变租约。

除非矩阵证明必要, 不保留永久后台激活线程。若必须保留, 应有显式状态、停止条件和用户说明。

## 8. 实机探针矩阵

### 8.1 探针前置修复

- 让 `--target-hwnd` 真正覆盖自动解析结果, 但仍执行 PID 和窗口身份校验;
- 修复 `WM_MOUSEWHEEL` 屏幕坐标;
- 增加 `--mouse-sequence` 选择, 每次只运行一种消息配方;
- 默认不发送输入; 必须显式 `--allow-input` 才进入倒计时;
- 所有输出继续保存在仓库外;
- 记录前后 foreground HWND 和 cursor position, 验证没有变化;
- 目标失效时立即停止并补发已记录的按钮释放消息。

### 8.2 待测序列

| 编号 | 激活 | 输入消息 | 目的 |
| --- | --- | --- | --- |
| M0 | 无 | Post MOVE + DOWN + UP | 最小纯消息基线 |
| M1 | 单次同步激活 | Post MOVE + DOWN + UP | 验证假激活需求 |
| M2 | 单次同步激活 | SendMessageTimeout MOVE/DOWN/UP | 验证同步消费 |
| M3 | 短租约激活 | Post MOVE + DOWN + UP | 验证队列与失活竞态 |
| M4 | 单次同步激活 | Post DOWN + UP, 不发 MOVE | 判断真实/消息位置来源 |

主窗口、中间窗口和叶子窗口可以在探针中分别验证, 但生产代码只能使用最终经身份验证的叶子窗口,
不能在运行时轮流猜测目标。

### 8.3 安全测试点

- 选择不会购买、删除、退出或提交账号操作的页面;
- 使用中心点和距四角至少 10% 的八个点形成九宫格;
- 另选至少三个可观察但可逆的按钮;
- 左键、右键、长按、拖拽和滚轮分开执行;
- 每次动作前由用户确认当前页面安全;
- 探针不连续高速点击, 单动作之间留出人工观察时间。

### 8.4 每条记录的最小字段

```text
timestamp
client_version
sequence_id
main_hwnd / leaf_hwnd / pid
window_class_chain
capture_size / content_rect / leaf_client_size
dpi
capture_point / leaf_point
foreground_before / foreground_after
cursor_before / cursor_after
api_dispatch_result
human_observed_result
notes
```

提交到仓库的证据只能包含脱敏汇总。原始截图、完整窗口清单、个人路径和 HWND 运行值不得提交。

### 8.5 通过条件

某项能力只有同时满足以下条件才能标为支持:

- 前台窗口在全部样本中保持不变;
- 系统光标在全部样本中保持不变;
- 目标失效和门禁失败时没有消息派发;
- 每个安全测试点连续 20 次至少成功 19 次;
- 不产生按钮粘住、持续视角移动或跨窗口输入;
- 1080p、1440p、2160p 中至少覆盖实际支持的两个档位;
- 窗口移动、最小化恢复和一次云客户端重连后重新验证;
- 结果由人工语义观察确认, 不能只依赖帧差。

若只有部分 UI 支持, 能力表必须按场景标记, 不得把局部成功推广为通用坐标点击。

- 消息后端未通过矩阵: 不接入任务, 保留键盘和截图能力, 鼠标能力标记为不支持;
- 接入后出现回归: 通过配置关闭云鼠标后端, 不切换到物理模式;
- Launcher 重构回归: 独立回滚目标选择 PR, 不影响消息构造模块;
- 客户端更新导致窗口链变化: 解析失败关闭, 更新探针证据后再修改正式身份条件;
- 任何误点其他应用的证据: 视为 P0, 立即停止发布并审查是否存在全局输入调用。

可阻止、可测试的消息, 并对不支持的能力诚实失败”。
